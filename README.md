# Погодный дашборд

Лабораторная работа № 8, вариант 1. Одностраничное приложение на нативном JavaScript без библиотек, фреймворков и сборщиков. Данные берутся у [Open-Meteo](https://open-meteo.com/): поиск городов (Geocoding API) и прогноз погоды (Forecast API). Ключ API не нужен.

Что умеет:

- искать город по названию и добавлять его в избранное (до 12 городов);
- показывать текущую погоду и прогноз на 5 дней для каждого города;
- фильтровать список по названию и по наличию осадков;
- сортировать по названию, температуре, осадкам и ветру (повторный клик меняет направление);
- сравнивать от 2 до 4 городов в таблице на 7 дней по температуре, осадкам или ветру;
- помнить города, фильтр, сортировку, выбор для сравнения и последний прогноз после перезагрузки страницы.

## Запуск

Браузер не загружает ES-модули с `file://`, поэтому нужен локальный сервер. Любой подойдёт:

```bash
cd weather-dashboard
python3 -m http.server 8080
# или: npm start
```

Откройте http://localhost:8080. Нужен современный браузер (Chrome, Firefox, Safari, Edge последних версий) и доступ в интернет к `open-meteo.com`.

## Структура

```
index.html            разметка с пустыми областями для динамического содержимого
css/styles.css        адаптивная вёрстка (Grid и Flexbox), светлая и тёмная тема
js/
  main.js             точка входа: store, события, запуск запросов
  state.js            состояние, reducer, селекторы, localStorage
  api.js              fetch: поиск городов и прогноз
  render.js           перерисовка интерфейса по состоянию
  dom.js              безопасное построение DOM (функция h)
  utils.js            debounce, форматирование
  weather-codes.js    расшифровка кодов погоды WMO
tests/unit.test.mjs   тесты логики (node --test)
```

Все модули — ES-модули в строгом режиме (`'use strict'`).

## Архитектура

Данные идут в одну сторону:

```
событие в DOM → main.js → store.dispatch(действие) → reducer → новое состояние → render.js → DOM
                                 ↑
                    api.js (результат запроса тоже приходит как действие)
```

**state.js.** Всё состояние живёт в одном объекте: избранные города, прогнозы, состояние загрузки и поиска, фильтр, сортировка, выбор для сравнения. Менять его можно только действием через `store.dispatch`. Reducer чистый: не обращается ни к сети, ни к DOM и не меняет прежний объект. Фильтрацию и сортировку считают селекторы (`selectVisibleFavorites`), в состоянии лежат только исходные данные. К store отдельно подключено сохранение в localStorage: сохраняются города, прогноз, фильтр, сортировка и сравнение, а состояние поиска и загрузки нет. При чтении каждое поле проверяется, и испорченное значение заменяется значением по умолчанию.

**api.js.** Знает только про сеть. Принимает параметры и `AbortSignal`, возвращает нормализованные данные или бросает `ApiError` с типом (`network`, `timeout`, `http`, `parse`, `data`). Прогноз для всех городов запрашивается одним запросом: Open-Meteo принимает списки координат. Отмена (`AbortError`) отличается от сбоя, поэтому отменённый запрос не показывается как ошибка.

**render.js и dom.js.** Каждая функция `render*` берёт состояние и перестраивает свою область страницы. Элементы создаются через `h(tag, props, ...children)`, текст попадает в DOM только как текстовый узел. Название города вроде `<img onerror=…>` отображается буквально и ничего не выполняет. `innerHTML` в проекте не используется. Поля ввода (поиск, фильтр) в перерисовке не участвуют, поэтому не теряют фокус и курсор.

**main.js.** Создаёт store, подписывает на него рендер (несколько действий подряд дают одну перерисовку) и сохранение, вешает обработчики. События делегированы: один обработчик `click` и один `change` на документе находят кнопку по `data-action`, поэтому после перерисовки карточек ничего не нужно перевешивать.

## Запросы и граничные случаи

| Ситуация | Поведение |
|---|---|
| Быстрый набор в поиске | debounce 400 мс: уходит один запрос с последним текстом. Enter запускает поиск сразу |
| Новый запрос, пока идёт старый | старый отменяется через `AbortController`, его ответ игнорируется |
| Запрос короче 2 символов | в сеть не уходит, показывается подсказка |
| Город не найден (ответ без `results`) | состояние «Город не найден», не ошибка |
| Источник недоступен, HTTP 4xx/5xx, не JSON | сообщение с кнопкой «Повторить»; ранее загруженный прогноз остаётся на экране с пометкой времени |
| Зависший запрос | таймаут 10 с |
| Долгая загрузка | индикатор и кнопка «Отмена» |
| Частое добавление и удаление городов | один запрос прогноза через 300 мс после последнего изменения |
| Пропуски в данных API | на экране «—» |
| Пустое избранное, пустой фильтр, нет выбранных для сравнения | отдельные сообщения |
| Браузер вернулся в сеть после ошибки | прогноз обновляется сам |
| localStorage недоступен или испорчен | приложение работает без сохранения |

## Тесты

```bash
npm test
```

Тесты на `node:test` проверяют reducer, фильтр и сортировку, сохранение и восстановление, испорченное хранилище, разбор ответов API, ошибки сети, отмену запроса и debounce. Зависимостей нет, нужен Node 18 и новее.
